The bridge is not production IPC: it imports the archive application in-process, uses an injected byte witness and has no native process identity. **Do not enable the bridge in production.**

## Protected sender / consumer split

**root-control protected owner:** independently authenticated installer pins exact Host, installation, persistent STATE identity, archive consumer `archive-mirror` and purpose `archive-mirror-upstream-fetch`, current authority revision, selected archive application source, executable and runtime process owner. The owner must hold its existing protected source ledger/lock, verify original signed authorization, receiver claim + delivery, and durably commit the one-time `installing` handoff **before** the first FD transmission. It must attest a fresh installed archive process identity, live boot and InvocationID, root-owned socket inode/peer, and selected UID/GID. Never accept a caller-supplied socket, UID, source key, group grant, or arbitrary destination path. A client cannot provide its own peer witness.

**archive-mirror app process:** installed separate non-root `app_uid`/`app_gid`, with installation-selected source SHA, private application store and exact authorized collection/role. The protected owner connects by a root-selected AF_UNIX endpoint. Kernel `SO_PEERCRED` must match exact protected process PID/UID/GID; native process manager additionally verifies starttime/cgroup, boot ID, service InvocationID, executable and socket inode to defeat PID reuse and wrong same-UID programs.

**Secret FD:** one `SCM_RIGHTS` FD only, over `AF_UNIX SOCK_SEQPACKET` only in this stricter extension; unframed SOCK_STREAM is denied. The FD is anonymous sealed `memfd` with `F_SEAL_WRITE|GROW|SHRINK|SEAL`, bounded bytes and CLOEXEC. It cannot be an ambient path, directory, symlink, regular disk file, inherited argv/env, journal record or local HTTP body. Control JSON contains **no secret**, only exact request, signed-delivery, scope, Host installation and revocation state references. Close every FD on rejection, reject multiple FDs, truncated ancillary packets and wrong sender.

**Acknowledgements:** only the selected native app/independent installed-byte attester may attest the actual destination bytes and a successful `install_verified` receipt; a caller boolean or in-process `inspect` cannot. A separately pinned Ed25519 attester signs exact Host/installation/STATE/boot, scope/delivery/request, authority revision, app installed source, monotonic sequence, fresh nonce and witness. Receiver records the terminal installation receipt only after this independently verified evidence.

**Revocation:** protected receiver first persists signed revocation hold, preventing new sends or opens, then the app writes the archive-mirror signed tombstone via `apply_signed_revocation`. A signed native revocation acknowledgement is inspected with fresh nonce/highwater; lost ACK, crash or reboot means reconcile the original operation and tombstone, never resend credentials or undo revocation. Archive retained objects/pins are never deleted by credential revocation.

## Source acceptance and native hold

`archive_provider_protected_ipc.py` implements disabled Linux source-validation and synthetic local socket/FD transfer helpers. Tests use non-root GitHub runners, disposable `socketpair` and a fake synthetic sealed secret, NOT the native separate app. They reject substituted peer PID/UID/GID, wrong source, wrong Host/STATE/authority revision, unsealed/disk/multiple FDs, stale or forged installed-byte/revocation ACK and re-delivery after a terminal receipt. No native installer, network socket listener, real protected authority, identity pin, key or long-lived credential is created.

**Native NO-GO until Work:** separate processes and current protected app identity; original mounted STATE proof; host-install protected UID/GID/service grant; socket path/inode, PID starttime/cgroup/InvocationID; actual independent installed-byte witness and attester signing key; native one-time ledger and reboot acceptance; no old in-process bridge fallback. All source candidates remain disabled and drafts.

## Reconciliation with current PR #22 disabled IPC v1

PR #22 also authored `archive_provider_ipc_contract.py` on the protected receiving-owner branch. **That v1 policy is the canonical disabled admission and installation-selection source**; PR #23's `archive_provider_protected_ipc.py` is a stricter process/FD/signed-ack extension, not a competing listener or an independent authority installer.

`verify_disabled_source_policy_compatibility` source-tests the exact same Host, installation, STATE, scope, credential and authorization revisions, archive purpose, selected non-root application UID/GID and source digest across both. It rejects either `enabled=True` or `native_accepted=True`. PR #22's original v1 stream-peer function is a synthetic shape predicate only; it is **not** selected transport framing. The stricter source extension requires atomic `SOCK_SEQPACKET` and rejects unframed STREAM and multiple/unsafe FDs. Both sets of source tests run in the same exact-head workflow.

PR #22's `validate_application_ack(..., witness_valid=True)` is **not native attestation**; the extension requires a separately installed, externally pinned Ed25519 attester and fresh signed ACK with monotonic highwater and original Host/boot/application identity. Neither a standalone boolean nor an in-process bridge may satisfy native acceptance.
