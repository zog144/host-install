## Distinct trust roots

The receiver retains its original installed Host UUID, installation UUID, STATE volume UUID, HostIdentity fingerprint, station signer public-key pin and managed registry; host-discover's signed monotonic checkpoint and host-install's **second owner ledger**, prepared certify-manage issuer UID/GID, persistent grant/storage, software view and controller record. The consumer's exact service ID, certificate SAN, DNS zone, credential UUID/revision, policy fingerprint and root-approved delivery policy must agree with the station's independently signed assignment. A shared control portal or the station's own public endpoint cannot establish the receiving Host identity.

The root-controlled cross-host client profile is **not** a replacement owner ledger. The installed readback `zog.host_install.issuer_cross_host_adoption.inspect` requires the original retained owner receipt, second owner ledger without a pending transaction, host binding, delivery policy, root approval, reader projection and client profile to agree at one exact current revision. The host-deploy `certificate_cross_host_admission.validate` also requires the exact Cloudflare UUID/revision (the signed owner records the `cloudflare-<UUID-without-dashes>` opaque source ID), DNS zone, grant/storage, issuer UID/state, approved hostnames/policy and valid expiration. A broker name alone is **not** sufficient.

The receiver checks installed source **and wheel RECORD** for `zog.root_control.issuer_https_receiver` at Git blob `3b6304793a8b8fc54ce63a8cb04e445ee1eb9943` from reviewed root-control source `31c1bf1d5d57534d595bf0c7f683f13186b24a48`, and `zog.host_deploy.certificate_cross_host_admission` at Git blob `ced728c5c8d7a2b1ced449091494e783680633c1`, with root-controlled package ancestry and exact selected Python interpreter. CI separately checks the coordinated station reader at `b9160c5b390594dc0ab90c58a7472acc04205f21`, Git blob `330618241601da041ac28292acdf163d2006ac41`; station-access source CI 40693427988 is PASS. Any later source must be separately pinned/reviewed before installation. The cross-host root-control source is an isolated bridge pin and does **not** replace the previously accepted certificate-controller root-control source identity used elsewhere by host-install. The selected root and host-deploy source packages must be installed *on the actual receiving host*. Only isolated, approved changes may update installed module bindings; never infer expected hash from a candidate's own bytes.

## Station-side HTTPS mapping is a separate precondition

The root-control station inspector `issuer_cross_host_ssh_admission.inspect` requires a real `protected HTTPS endpoint -T -C user=...` effective Match User configuration, an existing unique nonroot account and UID/GID equal the protected broker binding, one root-controlled authorized_keys entry with the exact Ed25519 key SHA256 and restrictive forced command, and no alternate password/authorized-key command/forwarding/PTY/shell path. The static result is insufficient by itself: native Work must prove an actual handshake with the reviewed key from the selected Host, a negative handshake with a different key, and real process UID/AF_UNIX SO_PEERCRED inside the station. The station broker socket and root-owned nonce directory must persist safely across reboot. HTTPS credentials are distinct from HostIdentity and station assignment Ed25519 signing keys.

## Native installation / adoption order

1. **No mutation preflight:** inspect the existing issuer service result and original InvocationID/journal from [host-install #2](https://github.com/zog144/host-install/issues/2). Any uncertain/active/pending preparation blocks transfer, and retained grants/storage must never be reset for this feature. Verify canonical STATE mount and both owner histories before and after.
2. **Source and root authority:** freeze approved root-control/station-access/host-install/host-deploy source revisions, wheel RECORDs, installed Python interpreter, station signer and receipt fingerprint, certificate policy, delivery consumer service ID, DNS-01 profile and prepared issuer runtime. Do **not** replace unrelated installed modules or change the current HTTP-01 artifact by implication.
3. **Protected station:** operator provisions exact reviewed station protected HTTPS endpoint key-to-UID match, one HTTPS authorized public key, fixed forced-command executable/arguments, dedicated nonroot bridge account, root-owned local broker listener and vault reader. No other HTTPS key, password, forwarding, SSM/HTTP/token export route. Verify restrictive root-owned socket, `SO_PEERCRED`, root projection and stable protected nonce storage. Native negative tests *without secret* come first.
4. **Protected Host:** separately approved root installer stages exact root-owned 0600 `<project-digest>.cross-host-client.json`, single-key 0600 known_hosts and client identity under reviewed filesystem path. It must preserve original issuer grant/storage/UID, bind exact preexisting owner ledger/projection and verify the installed source+wheel RECORD. Do not create a second project or use a new HostIdentity. Source `inspect` is **read-only** and returns `protected-source-preflight-only`, not `installed`.
5. **Dry-run and failure cases:** verify wrong key/principal, wrong Host/install/STATE/registry/signing pin, wrong assignment ID/revision, mismatched credential/zone/hostname/grant/storage/delivery policy, expired/revoked owner, swapped/extra authorized keys, stale source/RECORD, unsupported systemd unit, partial stream/nonce crash, simultaneous writers, reboot and rotation. No Cloudflare credential needs to be transmitted for these tests.
6. **Only after independent operator approval:** a privileged root owner may select root-control's exact `client-transfer` action for **one** approved request. That transfer independently rechecks the root approval and HTTPS identity on both sides and writes bytes only through the protected private FD to the original issuer `certificate-data/dns/cloudflare.ini`; check actual owner UID/GID, existing grant/storage and local installed ledger after. Never log plaintext token, its digest or raw HTTPS stdout.
7. **Separate selected issuer acceptance:** the original preparation recovery, authenticated inspect, staging ACME/DNS-01 and actual certificate/HTTPS publish/reboot remain independently authorized acceptance gates; none are enabled by source CI or a successful token transfer.

Use approved native owners/Work for steps that require access to the retained isolated station/Host. The GitHub source reviewers cannot attest installed bytes or execute the real forced-command mapping remotely from this chat.

**Stop:** no remote token, Cloudflare/DNS mutation, ACME command, nginx reload or production activation has occurred as a result of this source review.
