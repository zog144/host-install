# Managed beacon and enrollment boundary

## Narrow optional profile

Host-install can explicitly prepare the host-discover root supervisor after live STATE verification and identity consumption. The managed-beacon profile binds installation, STATE volume and consumed fingerprint; it enables enrollment/session-bound heartbeats under a separately accepted station authority, not general remote commands or archive/root-control dispatch.

## Durable session ownership

The root-owned supervisor ledger and station managed-session history retain pending session requests, boot challenge, epoch/checkpoint and exact signing bindings. A lost response or reboot must reconcile the recorded request; a missing or mismatched ledger is not permission to begin a fresh history. Provisioning and upgrades require explicit owner action rather than being inferred from existing service files.

## Separation from browser approval

Host-identify owns signing material, host-discover the supervised client, station-access approval and scope. Station session acceptance is independent from AWS inventory, archive grants and DNS name ownership. Local source fixtures do not prove combined live HTTPS, supervisor, bound port or reboot recovery.
