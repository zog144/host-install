# Protected archive-provider IPC v1 — source contract (2026-11-03)

**OFFLINE SOURCE ONLY; disabled, not native-approved.** Companion of host-install PR #22, archive-mirror #2. This document defines a separately owned root-control -> archive-mirror *application* boundary. The current in-process `ArchiveProviderHandoff` is a synthetic test exercise, **not** an IPC or production credential receiver. No service/socket provisioning or actual credential delivery.

## Required identities and sequence

- Independently installed protected policy selects exact Host / installation / authenticated STATE / archive provider scope / credential revision / authorization revision, root receiver uid **0**, dedicated nonroot archive application UID/GID, independently pinned Credential Authority key, and a specific receiver scope. The authenticated Host request and signed delivery are verified by the protected owner **before** any descriptor crosses the process boundary.
- Connection must be AF_UNIX stream on an owner-provisioned protected pathname `/run/zog/archive-provider-credential.sock`. Peer identity must be established via Linux `SO_PEERCRED` (PID+UID+GID), additionally checked against the *selected* process identity and installed source provenance; pathname socket permissions or a claimed JSON UID alone are insufficient. Root sender and archive UID receiver authenticate one another on their respective connected sockets. No `root-control.sock`, Cloudflare-purpose, generic RPC or inherited station credentials.
- The root owner commits its canonical request, nonce, delivery identity, and irreversible `installing` fence before transfer. Exactly **one** `SCM_RIGHTS` descriptor accompanies the narrowly scoped request, no secret in JSON, HTTP, argv, env or journal. Descriptor must be an anonymous `memfd` with zero hardlinks, exact size, exact digest (verified privately), and all four `F_SEAL_*` seals; reject extra/absent/truncated descriptors or named/unsealed regular files. Receiver closes all copies and never exposes secret bytes in receipts. Native consumer must use the actual FD (or a documented equivalent) rather than decode/re-encode a secret in a root process.
- Archive-mirror *as the nonroot application owner* alone invokes `install_verified` into its 0700/0600 private state and commits its own durable installation identity. The native API **still needs** a consumer FD adapter; the existing source `install_verified(scope,authorization,request,delivery)` decodes an in-memory secret, so the source IPC predicates here must not be misrepresented as full installation isolation.
- On ambiguity, root-control asks the archive application to inspect the independently verified installed metadata and byte witness; **never** resends the FD or calls the installer again. Original consumer UID/GID, exact source/wheel revisions and secret byte equality must all be independently witnessed before a durable canonical installation receipt. Lost acknowledgement permits read-only reconciliation, not fresh delivery.
- A root-owned common revocation deny is durable first. The application then receives the independently verified signed revocation **without a credential FD**, calls `apply_signed_revocation` and persists a nonsecret application acknowledgement. Repeating the identical signed revocation after a crash is permitted; repeating a credential delivery is not. Archive objects, catalogue rows and pins remain unchanged.
- Application acknowledgements must bind exact Host, installation, STATE, scope, consumer/purpose, request/delivery IDs, credential/authorization revisions, nonroot UID/GID, phase and cryptographically/provenance-verified installed-byte or tombstone evidence. A bare `status=installed`, hash, or synthetic Python boolean from the caller is not an admissible native witness. `validate_application_ack` performs **only shape/identity source validation** on a previously verified witness; it does not authenticate a peer or sign a receipt.

`src/zog/host_install/archive_provider_ipc_contract.py` implements disabled policy predicates, Linux socket peer extraction, exact one-sealed-memfd transfer validation, and source-only ack matching. Its tests use same-process ephemeral sockets and synthetic FDs and therefore **cannot establish actual root-to-unprivileged UID separation**. External root-control installation/IPC, station pin provenance, native process ownership, private archive storage, transport signature, rollback/reboot recovery and installed-byte receipts remain **NO-GO**. The code intentionally cannot switch `enabled` or `native_accepted` to true.

## Native acceptance checklist

A separate root-control consumer integration must add cross-UID process tests, rejected impersonation/wrong-GID/fd swap, sealed-FD close-on-error, dual-writer and ledger anti-rollback, cancellation/revocation races, exact installed-byte witness under the archive UID, and reboot receipts. No automatic authority replacement or expansion. The synthetic bridge stays disabled and cannot substitute for native proof.
